# Render Staging Deployment

This project can deploy to Render as two Docker web services:

- `clinic-ai-copilot-api-staging` - Express API
- `clinic-ai-copilot-web-staging` - built Vite frontend served by Nginx

The root `render.yaml` file is a Render Blueprint. Render reads it from the
repository root and builds each service from the Dockerfile path listed in the
file.

## Before Creating The Blueprint

Create or choose a MongoDB Atlas database for staging. Do not point staging at
real patient data.

Have these values ready:

```env
MONGO_URL=replace_with_staging_mongodb_atlas_url
DEMO_DOCTOR_PASSWORD=replace_with_staging_demo_password
OLLAMA_URL=replace_with_reachable_ollama_url
```

`JWT_SECRET` is generated by Render from the Blueprint.

## Create The Render Blueprint

1. Open Render Dashboard.
2. Choose **New** -> **Blueprint**.
3. Connect the GitHub repo.
4. Select branch `main`.
5. Keep the Blueprint path as `render.yaml`.
6. Render will prompt for values marked `sync: false`.
7. Enter the staging `MONGO_URL`, `DEMO_DOCTOR_PASSWORD`, and `OLLAMA_URL`.
8. Deploy the Blueprint.

## Confirm Service URLs

The Blueprint expects these URLs:

```text
https://clinic-ai-copilot-api-staging.onrender.com
https://clinic-ai-copilot-web-staging.onrender.com
```

If Render changes either URL because of a name collision, update:

- API service `CORS_ORIGINS`
- Web service `VITE_API_BASE_URL`

Then redeploy both services.

## Seed Staging

After the API service deploys successfully:

1. Open the API service in Render.
2. Open **Shell**.
3. Run:

```bash
yarn api:seed
```

The seed script uses the staging `MONGO_URL` and demo doctor values from the
Render service environment.

## AI Summaries On Staging

Local Ollama URLs such as `http://localhost:11434` do not work from Render.
`OLLAMA_URL` must point to an Ollama server that the Render API service can
reach over the network.

If no reachable Ollama server is configured, the rest of the app can still run,
but AI summary generation will fail when used.

## Smoke Test

After both services deploy:

1. Open the web staging URL.
2. Sign in with the seeded demo doctor.
3. Confirm patients load.
4. Open an appointment.
5. Save a clinical note.
6. Generate an AI summary only if `OLLAMA_URL` is configured.
